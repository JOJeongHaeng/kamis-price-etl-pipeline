## 1. 결정 요약
본 프로젝트는 원래 목표였던 "농산물 가격 ZIP 원천파일 전회차 자동 수집/정제/적재/분석 파이프라인" 관점에서 폐기한다.

폐기 사유는 구현 난이도 자체보다 원천 데이터 품질과 형식 불일치가 심각하여, 안정적인 운영 수준의 자동화 파이프라인을 만들기 어렵기 때문이다.

## 2. 폐기 결정 사유
### 2.1 원천 구조 불일치
- ZIP 내부 파일 구성이 회차별로 다르다.
- 동일 목적 문서라도 파일명, 포맷, 표 레이아웃이 일정하지 않다.
- 일부 회차는 `xlsx + pdf`, 일부 회차는 `pdf` 중심이며, 초기 회차는 이미지형 PDF 비중이 높다.

### 2.2 PDF 의존도 과다
- 전체 원천 중 PDF 비중이 높다.
- 텍스트형 PDF는 일부 자동 추출이 가능하지만, 다수는 OCR이 필요하다.
- OCR 결과는 표 구조, 날짜 범위, 품목명 정렬이 안정적이지 않다.

### 2.3 운영 품질 확보 실패 위험
- `423`, `-1.8%`, `(국산))` 같은 오염 데이터가 실제 적재된 사례가 있었다.
- 정제 규칙으로 일부 방지는 가능하지만, 이미지형 PDF 전회차에 대해 같은 품질을 보장하기 어렵다.
- 전회차 자동 적재를 운영하려면 수작업 검수 비용이 계속 발생한다.

### 2.4 비용 대비 효과 부족
- 파이프라인 개발보다 원천 복원과 예외 처리에 더 많은 비용이 든다.
- 전회차 완전 자동화 목표는 현재 원천 품질과 맞지 않는다.

## 3. 현재까지 완료된 작업
- MySQL 스키마 설계 및 적재 경로 구성
- `Item`, `Week`, `WeeklyPrice`, `MarketPrice`, `WeeklyReport` 중심 적재 구조 구현
- 텍스트형 PDF 일부에 대한 가격/리포트 추출 경로 구현
- 이미지형 PDF OCR 가능성 검증
- 비정상 품목 필터링 규칙 정리 및 회귀 테스트 추가

## 4. 현재 한계
- 이미지형 PDF 다수에서 날짜 범위 추출 실패
- OCR 텍스트의 행 정렬 불안정
- 주차 정보와 가격 행의 정확한 매핑 어려움
- 문서 유형별 예외 케이스가 많아 일반화 비용이 큼
